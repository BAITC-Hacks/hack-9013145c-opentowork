## 1. Задача

**Название Задачи:** Agentic AI для прогнозирования выработки ВЭС, трек 01 «Энергетика».

**Суть требований** (по нашему разбору; текст ТЗ в репозитории не сохранён —
**критерии оценки перенести сюда дословно из оригинала ТЗ**):
- почасовой прогноз выработки ВЭС на горизонт 24–48 часов;
- проверка walk-forward на тестовом периоде: февраль 2026, данные турбин с марта 2023;
- агент сам получает погоду по координатам станции, считает, анализирует и пересчитывает прогноз;
- для прогноза используются **архивные прогнозы погоды на момент выпуска, а не фактическая погода**:
  иначе в модель утекает будущее.

**Данные организатора:** SCADA двух турбин (`datasets/turbine_1.csv`, `turbine_2.csv`),
03.2023–01.2026. Номинальная мощность в данных не указана — выработка считается в долях номинала.

## 2. Продукт

**Пользователь:** диспетчер ВЭС, который подаёт суточный план выработки.

**Боль:** план на сутки вперёд строится по одному погодному прогнозу или по
«как вчера»; ошибка плана оборачивается штрафами за небаланс, а момент, когда
погода изменилась и план пора пересчитать, никто не отслеживает.

**Что меняется:** почасовой прогноз с интервалом P10–P90 и текстовой сводкой;
агент сам пересчитывает прогноз при выходе нового выпуска погоды. На годовом
бэктесте (365 выпусков, 02.2025–01.2026) MAE ансамбля 0.158 против 0.172
у «сырой погоды + кривой мощности» и 0.363 у «как вчера».

**Почему тут нужен AI:** ML-модели исправляют систематические ошибки погодных
моделей на конкретной площадке; агент принимает решения по шагам (какой выпуск
погоды свежий, достаточно ли моделей, нужен ли пересчёт), а Copilot отвечает на
вопросы диспетчера по рассчитанным фактам с проверкой чисел.

---

## 3. Демо-сценарий

Пошагово — README, раздел «Проверка основного сценария → Вручную».

1. Диспетчер открывает станцию Нурлы (`/#/forecast/wind/nurly`) и выбирает день тестового периода.
2. Видит почасовой прогноз на 48 ч с P10–P90 и шаги агента, который его построил.
3. Переключает горизонт на 24 ч, открывает турбину, смотрит бэктест против базовых моделей.
4. Спрашивает Copilot «Когда ожидается пик?» и «Что, если ветер на 15% слабее?» —
   ответ содержит ID выпуска и список выполненных инструментов.

**Чем докажем, что это не обёртка над чатом:** ответ Copilot строится из
инструментов агента (`meta.tools`) и привязан к конкретному выпуску прогноза;
числа в тексте LLM сверяются с рассчитанными фактами; тест утечек будущего
подменяет весь «будущий» архив погоды мусором и проверяет, что признаки не меняются.

## 4. Маппинг на каркас

### 4.1 Доменная логика
Прогноз ВЭС вынесен в отдельный пакет `windcast/`, а не в `DomainEntity`: ему нужны
почасовые ряды и артефакты моделей, а не CRUD. `DomainEntity` и `/entities` остались
от платформенного каркаса и в демо не используются. Справочник ветровых станций
Казахстана — таблица из миграции `0004`, эндпоинт `/stations`.

### 4.2 Контекст семантического кэша
`CACHE_CONTEXT_FIELDS=language,region,doc_kind`. Ответы Copilot по прогнозу
(`context.forecast_id`) **не кэшируются**: разные выпуски и сценарии нельзя смешивать
по близости текста вопроса.

### 4.3 Доменные правила валидации
`RANGE_RULES` в `app/domain/rules.py` **не заполнены**. Проверка чисел для прогноза
сделана иначе: `app/wind/copilot.py` собирает факты прогона, и в live-режиме общий
валидатор (`app/ai/validator.py`) отклоняет ответ LLM с числами, которых в этих
фактах нет. Отчёт агента (`windcast/agent/report.py`) при выдуманном числе
оставляет шаблонный текст.

### 4.4 База знаний для RAG
Сид-документы — общие, о платформе (`app/scripts/seed.py`). Источником для Copilot
служат не документы, а факты прогона агента (`app/wind/copilot.py`).

### 4.5 Структура ответа модели
`AIAnswer` без изменений; в `meta` добавлены `tools` — список инструментов,
выполненных при ответе.

## 5. Что сделано сверх основного сценария

Показывается как потенциал масштабирования. Это **не** доказательство качества
ML-модели на новых площадках.

| Экран | Что считает | Честная оговорка |
|---|---|---|
| Другие ВЭС Казахстана | прогноз «сейчас» по погоде Open-Meteo | модель — кривая мощности Нурлы, не ML; P10–P90 — эвристика |
| Новая площадка → ВЭС | выработка новой турбины за 24–48 ч (windpowerlib) | нужен интернет у API |
| Новая площадка → СЭС | карта ресурса по региону | синтетическая, помечена «Демо» |
| Крыши города | потенциал 481 крыши левого берега Астаны с учётом теней | физический расчёт (PVGIS + OSM), не ML; 44% высот — допущение |

## 6. Чего нет

- Факта выработки за февраль 2026: качество тестового периода оценено только бэктестом.

- Нагрузочного теста: цифры пропускной способности не измерялись.
- Заполненных `RANGE_RULES` и доменного RAG (см. 4.3–4.4).

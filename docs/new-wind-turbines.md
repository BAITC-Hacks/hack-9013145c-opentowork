# Расчёт новых ветровых турбин

Модуль `app/wind/` считает предварительную выработку виртуальной турбины по
координатам и характеристикам. Обучаемая WindCast для двух турбин кейса остаётся
отдельной системой: её локальные поправки и интервалы здесь не применяются.

## Запуск и интерфейс

Установить обновлённые зависимости (`pip install -e ".[dev]"`) или пересобрать
контейнеры `docker compose up -d --build`. На фронтенде: **Новая площадка → Ветровые станции**,
адрес `/#/place/wind`. Для расчёта нужен доступ бэкенда к Open-Meteo.

1. Нажать на существующую карту Казахстана или ввести широту и долготу.
2. Выбрать модель, доступную высоту башни, горизонт 24/48 ч и потери 0–30%.
3. Нажать «Рассчитать выработку».
4. Посмотреть почасовую мощность, энергию в МВт·ч, использование номинала,
   ветер у ротора и происхождение данных.
5. Добавить до трёх вариантов к сравнению. Варианты существуют только на этом
   экране; после ухода или перезагрузки они сбрасываются.
6. «Добавить турбину на карту» сохраняет конфигурацию в этом браузере. Можно
   хранить до 12 турбин; они появляются на карте и в «Мои новые турбины».
   Сохранение переживает перезагрузку. Выбор турбины заполняет форму; для свежего
   прогноза нажать «Рассчитать выработку». Удаление доступно в карточке.

Используется общая `KzMap` с существующим контуром страны и справочником ВЭС.
Карта не изображает ветровой ресурс или пригодность участка. Можно ввести
координаты за её пределами. Погодный расчёт использует введённую
точку, а ответ также содержит координаты ячейки погодной модели.
Пользовательские конфигурации — локальные черновики, не записи общего реестра
ВЭС. Синхронизация между устройствами и аккаунтами отсутствует.

## API

Оба маршрута требуют обычный Bearer-токен проекта.

### `GET /api/v1/wind/turbine-models`

Три модели с кривыми и допустимыми высотами из закреплённого снимка
[OEDB/windpowerlib](https://github.com/wind-python/windpowerlib/tree/191d8ca894d6d830997630fa3599f048d6e8c7b4/windpowerlib/oedb):

| ID | Номинал | Высоты, м |
|---|---:|---|
| `ge-100-2500` | 2500 кВт | 75, 85 |
| `enercon-e101-3050` | 3050 кВт | 99, 124, 135, 149 |
| `enercon-e126-7580` | 7580 кВт | 127 |

Это каталог для сравнения; он не подтверждает доступность поставки или пригодность
этих комплектаций для Казахстана. Кривые и метаданные сохранены в `turbines.json`,
ссылки на их конкретную версию возвращаются API. Лицензия исходного репозитория
сохранена в `UPSTREAM-LICENSE.txt`. Пересборка: `python scripts/build_wind_catalog.py`.
Сеть нужна только для пересборки каталога, при обычном запуске он локальный.
Загрузчик оборудования — `app/wind/turbines.py`. Существующий
`app/wind/catalog.py` продолжает загружать реестр станций и не изменён.

### `GET /api/v1/wind/reference-turbines`

Оборудование действующих ВЭС Казахстана (проекты группы Самрук-Энерго) — только
паспорт, **без расчёта выработки**. Данные в `app/wind/reference_turbines.json`,
сверены с первоисточниками 23.09.2026:

| ID | Модель | Где стоит | Источник |
|---|---|---|---|
| `goldwind-gw130-2500` | Goldwind GW130-2.5MW, ротор 130 м | Шелекская ВЭС 60 МВт, 24 шт. | пресс-релиз Goldwind; Самрук-Қазына |
| `fuhrlaender-fwt-2050` | Fuhrländer Wind Technology 2,05 МВт, ротор 93 м, башня 85 м | Ерейментауская ВЭС 45 МВт, 22 шт. | Самрук-Энерго; оператор ПВЭС |
| `goldwind-gw109-2500` | Goldwind GW109-2.5MW, ротор 109 м | Шелек, межправительственный проект | пресс-релиз Goldwind |

**Почему без расчёта.** Для расчёта нужна кривая «скорость ветра → мощность».
Производители её не публикуют, в OEDB/windpowerlib этих моделей нет (ни в
закреплённой версии, ни в актуальной; из Vensys, на платформе которой выросли
Goldwind 2.5 МВт, кривая есть только у VS112/2500). Номинала, ротора и границ
3/12/25 м/с недостаточно, а кривая другой турбины под этим названием была бы
подменой. `POST /simulate` с таким `turbine_id` отвечает 422 с объяснением.
Связь GW109-2.5MW с турбинами ВЭС Нурлы из данных кейса не подтверждена:
производитель называет Шелек, в OSM у Нурлы указана GW109/2500 без источника.

Чтобы модель стала расчётной, нужен паспорт производителя с таблицей кривой —
её добавляют в `turbines.json` со ссылкой на документ.

### `POST /api/v1/wind/simulate`

```json
{
  "latitude": 51.62,
  "longitude": 73.1,
  "turbine_id": "ge-100-2500",
  "hub_height_m": 85,
  "horizon_hours": 48,
  "loss_percent": 5
}
```

Если высота не указана, используется первая доступная. Невалидные координаты,
высоты, горизонт и потери дают 422, неизвестная турбина — 404. Неизвестные поля
запрещены, включая историческую дату `origin`: этот сервис не выполняет бэктест.
Недоступная или неполная погода даёт 503 без замены синтетическими числами.

Ответ содержит `hours`, `net_energy_kwh`, `gross_energy_kwh`, `capacity_factor`,
`forecast_start`/`forecast_end` (конец исключён), параметры запроса и турбины,
`weather_retrieved_at`, координаты погодной ячейки и `assumptions`.
`calibrated` всегда `false`, метод — `engineering_power_curve_v1`.

## Расчёт

- [Open-Meteo Forecast](https://open-meteo.com/en/docs), автоматический выбор
  погодных моделей `best_match`: ветер 10/80/120/180 м в м/с, температура 2 м
  в °C, **поверхностное**, а не приведённое к уровню моря давление в гПа.
- Времена UTC, начало — следующий полный час, 24 или 48 последовательных часов.
  Фронтенд показывает UTC+5. Время получения сохранено отдельно от времени
  выпуска погодного прогона: последнее неизвестно и остаётся `null`.
- Ветер у ротора — линейная интерполяция скорости по логарифму высоты между
  соседними доступными уровнями. Экстраполяции за 10–180 м нет.
- Температура у ротора: градиент −0.0065 K/м от уровня 2 м. Давление —
  барометрическая поправка на высоту башни; плотность — закон идеального газа
  для сухого воздуха. Влажность не учитывается.
- `windpowerlib.power_output.power_curve(..., density_correction=True)`;
  опорная плотность принята 1.225 кг/м³. Это допущение расчёта для каталога,
  а не подтверждение паспортных условий каждой конкретной комплектации.
- Высокоскоростные нулевые точки отделены от поправки на плотность, чтобы
  плотность не сдвигала границу остановки. До этой границы продлевается последнее
  рабочее плато. Для текущих трёх кривых граница — 25.5 м/с по таблицам;
  реальные штормовые режимы контроллеров, задержки и гистерезис не моделируются.
- Выход ограничен диапазоном 0…номинал. Для E-101 исходная кривая достигает
  3000 кВт при номинале 3050 кВт; расхождение сохранено и отмечено в ответе.
- Пользовательские потери применяются после кривой. Энергия — сумма мощностей
  × 1 час. Погодная скорость в часовой точке принята представительной для часа;
  внутривременная изменчивость и нелинейность при усреднении не восстановлены.

Кэш успешных погодных ответов ограничен 128 записями на процесс, TTL 900 с.
Ключ: координаты, первый прогнозный час и горизонт; смена оборудования для
одной точки может использовать ту же погоду. Неполная погода не кэшируется.
Настройки в `app/config.py`: `WIND_WEATHER_URL`, `WIND_WEATHER_TIMEOUT_S`,
`WIND_WEATHER_CACHE_TTL_S`, `WIND_WEATHER_CACHE_SIZE`.

## Границы результата

Нет локальной калибровки, вероятностных интервалов, эффектов следа соседних турбин,
поправок на рельеф и застройку, отключений сети, обледенения и температурных
ограничений комплектации. Это расчёт мощности, а не разрешение на строительство
и не заключение о пригодности оборудования.

Двое суток не характеризуют годовой потенциал. Для сравнения использовать
одинаковые периоды, координаты и потери; смотреть также МВт·ч на 1 МВт номинала.
Чтобы улучшить оценку в будущем: добавить подтверждённые кривые конкретных
комплектаций, локальные измерения и проверить поправки на отдельном периоде.

## Проверка

```bash
python -m pytest tests/test_wind.py -q
python -m scripts.smoke_wind
cd frontend
npm ci
npm run build
```

Юнит-тесты без сети и БД: эталонные точки кривых, плотность, высота, остановка,
единицы энергии, потери, полные временные ряды, единицы погоды, кэш, ошибки
провайдера, валидация API и авторизация. `smoke_wind` использует реальный интернет
и проверяет работоспособность; он не измеряет точность прогноза по SCADA.

Проверено после обновления команды `7865993`: 41 тест (новый модуль, API
WindCast и солнечный модуль), `ruff check .`, TypeScript + Vite build.
На Windows тесты запускались с `python -X utf8 -m pytest ...`.
В браузере проверены общий интерфейс, расчёт по реальной погоде, добавление
турбины и восстановление после перезагрузки. Для UI использован временный
локальный стенд без БД; авторизация нового API отдельно покрыта тестами.
Рабочий Docker-стек в этом запуске не поднимался.

# Что нашло внешнее ревью и что с этим сделано

Внешний разбор проекта 23.09.2026. Главный вывод ревьюера стоит запомнить
дословно: **комментарии обещали больше, чем делал код**. Это и чинили в первую
очередь — не текст комментариев, а код, чтобы утверждения стали правдой.

Ниже — полный список. Каждая строка либо исправлена, либо честно помечена как
неисправленная с причиной. Раздел «осталось» важнее раздела «сделано»:
на защите спросят именно про него.

---

## Исправлено: безопасность

| Дефект | Было | Стало |
|---|---|---|
| **Полный обход аутентификации** | `secret.yaml` с `JWT_SECRET: REPLACE_ME` подключён к `kustomization.yaml`; код молча принимал дефолт | Шаблон секрета отключён от базового набора. `Settings` **падает на старте** при `APP_ENV != dev`, если секрет дефолтный или короче 32 символов |
| **Публичный ADMIN-бэкдор** | `SEED_ON_START=True` по умолчанию, демо-учётка с ролью `ADMIN` и паролем из README | Сид выключен по умолчанию; роль задаётся `DEMO_USER_ROLE`, по умолчанию `EXPERT` — она не обходит проверку владельца |
| **Утечка ответов между пользователями** | `SEMANTIC_CACHE_SCOPE=global` в проде; воркер не передавал `user_id` вовсе | По умолчанию `user`; воркер получает владельца в payload. Покрыто тестом `test_cache_does_not_leak_between_users` |
| **База знаний общая для всех** | В RAG-запросе не было ни одного фильтра по владельцу | Колонки `owner_id` и `visibility`; retrieval отдаёт только публичные документы и собственные. Тест `test_private_document_is_invisible_to_others` |
| **Guard обходился через `context`** | Проверялся только `query`; `context` уходил в промпт дословно и без лимита | `context` сканируется и ограничен `CONTEXT_MAX_CHARS`; PII маскируется и в нём |
| **Подделка источников через заголовок документа** | `title` подставлялся в атрибут без экранирования | `quoteattr` и `escape`; тесты на подделку `doc id` и выход из блока контекста |
| **Осиротевшие объекты — общедоступны** | `if record.user_id:` пропускал проверку при `NULL` | `authorize_owner` отказывает при `owner_id is None` всем, кроме ADMIN |
| **OOM при загрузке файла** | `await file.read()` целиком, лимит проверялся после | Проверка `Content-Length` до чтения + чтение кусками с обрывом на лимите; `client_max_body_size 20m` в nginx |
| **Rate limit на 4 эндпоинтах из 15** | Не закрыты поиск, загрузка документов, создание задач, файлы, статистика | Закрыты все перечисленные; вход ограничен по email **и по IP** (`X-Forwarded-For`) |
| **User enumeration по таймингу** | При отсутствии пользователя argon2 не вызывался | Добавлен `waste_password_time()` с фиктивным хэшем |
| **`except (VerifyMismatchError, Exception)`** | Глушил в том числе битый хэш в базе | Разделены: неверный пароль — `False`, битый хэш — ошибка в лог |
| **Swagger наружу в проде** | `docs_url` захардкожен | Отключается при `APP_ENV=prod`, если не включён `DEBUG` |
| **Имя файла в ключ S3 без очистки** | Слэши и `..` управляли структурой ключей | `safe_filename`: путь отбрасывается, управляющие символы вычищаются. Кириллица сохраняется |
| **Логи маскировали только верхний уровень** | Секрет внутри `context` попадал в лог | Рекурсивная маскировка; `redact()` больше не мёртвый код |
| **Кардинальность метрик без предела** | Сырой URL в лейбле при 404 | Несматченные маршруты → `__unmatched__` |
| **Нет CSP и заголовков безопасности** | Токен в `localStorage` без единой защиты | CSP, `X-Frame-Options`, `nosniff`, `Referrer-Policy`, `Permissions-Policy` в nginx |
| **CI без проверок безопасности** | Ни одного сканера | `gitleaks`, `pip-audit`, `bandit`, `trivy` |

## Исправлено: масштабируемость и корректность

| Дефект | Было | Стало |
|---|---|---|
| **Воркер — одна задача за раз** | `count=1`, последовательная обработка; event loop простаивал на ожидании модели | `WORKER_CONCURRENCY=8`, параллельная обработка пачки |
| **«At-least-once» не соответствовал коду** | `ack` вызывался безусловно, в том числе после ошибки → фактически at-most-once | `ack` только при успехе; транзиентная ошибка оставляет сообщение неподтверждённым, оно возвращается через `reclaim_stale`. Исчерпавшие попытки уходят в поток `ai_jobs:dead` |
| **Redis-поток рос до OOM** | `xadd` без `maxlen`, `XTRIM` не вызывался | `QUEUE_MAX_LEN` с приблизительной подрезкой |
| **`depth()` считал всю историю** | `XLEN` — число всех задач за всё время | `lag + pending` из `XINFO GROUPS`; метрика `QUEUE_DEPTH` наконец заполняется |
| **Dual-write без компенсации** | `enqueue` до коммита транзакции | Коммит → постановка в очередь → при сбое 503 клиенту; восстановительный проход воркера подбирает задачи, не попавшие в очередь |
| **Гонка идемпотентности** | SELECT → INSERT давал `IntegrityError` и 500 | `ON CONFLICT DO NOTHING` + повторный SELECT |
| **Отмена задачи декоративна** | Статус проверялся только в начале | Проверяется и после ответа модели |
| **Блокирующий boto3 в корутине** | Вставал весь event loop пода | `asyncio.to_thread` на загрузке и presigned-ссылке |
| **Индексация: вызов на каждый чанк** | Сотни последовательных HTTP-запросов внутри одного запроса | `embed_many` с батчами по 64; размер документа ограничен |
| **Тихая деградация recall у HNSW** | Фильтр применяется после обхода индекса; при `ef_search=40` запрос возвращал пусто при наличии записи | `hnsw.ef_search=200` через `set_config` перед фильтрованным поиском |
| **Нет версии эмбеддера** | Векторы разных моделей смешивались молча | Колонка `embedding_model` в `knowledge_chunks` и `semantic_cache`; поиск фильтрует по ней |
| **Двойной учёт токенов** | Инкремент и в провайдере, и в оркестраторе — в проде цифры вдвое завышены | Считает только оркестратор |
| **`/ai/stats` — шесть полных сканов** | Без окна, без лимита, доступно всем | Один проход за окно `STATS_WINDOW_HOURS`, под rate limit |
| **`TRIM_SQL` во всех воркерах разом** | Сортировка всей таблицы каждые 300 с в каждом поде | Блокировка в Redis: чистит один воркер |
| **Валидатор проверял только первую цифру** | `break` после первой находки; `possible_causes` не проверялись вовсе | Собираются все необоснованные числа; проверяются и причины, и рекомендации; белый список сокращён до `0,1,2` |
| **PATCH не мог очистить поле** | `exclude_none` | `exclude_unset` |
| **500 вместо 422** | `uuid.UUID(...)` на некорректной строке | Явная проверка |
| **Базовый K8s-оверлей не поднялся бы** | `POSTGRES_PASSWORD: REPLACE_ME` против `app:app` в `DATABASE_URL` | Пароль согласован; локальный оверлей генерирует свой секрет |
| **Мёртвая конфигурация** | `OTEL_*` объявлены и нигде не читались; OpenTelemetry заявлен в README | Удалены из конфига, из README, помечены как нереализованные в `docs/06` |
| **CI не собирал фронтенд** | Поломка вёрстки доезжала до развёртывания | Собирается; добавлена задача интеграционных тестов с настоящей базой |
| **Ни одного теста на границы доступа** | 24 теста, все юнит | 45 тестов: 36 юнит + 9 интеграционных на authz и изоляцию |

## Не исправлено — и почему

Честный список. Каждый пункт — осознанное решение, а не забытое.

| Что | Почему отложено | Риск |
|---|---|---|
| **Отзыв токенов**: `jti` генерируется, но денилиста нет; logout отсутствует; refresh не ротируется | Нужен стор отозванных токенов и пересмотр жизненного цикла сессии | Смена роли или бан не действуют до истечения токена (до 60 мин / 7 дней) |
| **Проверка `iss` / `aud`** | Один эмитент, вопрос не стоит | Низкий в текущем контуре |
| **PII пишется в базу открытым текстом** | `strip_pii` защищает вендора, но `messages.content` и `ai_requests.query` хранят оригинал. Нужно решение: шифровать, маскировать или не хранить | **Высокий для регулируемого кейса.** Решать вместе с постановщиком Задачи |
| **Токен в `localStorage`** | Переход на httpOnly-cookie требует CSRF-защиты и переработки авторизации | Снижен добавлением CSP, но XSS всё ещё означал бы угон сессии |
| **Фронт не обновляет токен по refresh** | Сессия живёт 60 минут, для демо достаточно | Пользователя выбрасывает на вход через час |
| **Нет `NetworkPolicy`, `seccompProfile`, `automountServiceAccountToken: false`** | Усиление кластера, а не приложения | Средний в проде |
| **Redis без пароля; Postgres/Redis/MinIO проброшены на хост в compose** | Локальный стенд; в проде порты не публикуются | Средний, если стенд окажется в сети |
| **Пул соединений не посчитан** | 10+5 на под × 30 подов ≈ 450 против дефолтных 100 у Postgres. Нужен PgBouncer | **Жёсткий потолок раньше любого HPA** |
| **Индексация документа синхронна** | Размер ограничен и эмбеддинги батчатся, но крупный документ всё ещё держит запрос | Средний; правильное решение — отправить в очередь |
| **HPA воркеров по CPU** | KEDA по длине очереди требует установки оператора; конфигурация лежит закомментированной в `hpa.yaml`. Метрика `queue_depth` теперь есть — данные для перехода готовы | Масштабирование по неверному сигналу: CPU простаивает, пока воркер ждёт модель |
| **Запись в Redis-кэш не транзакционна с INSERT** | Откат транзакции оставляет запись в exact cache | Низкий: TTL час, ответ валидный |
| **Образы `latest`, CI ничего не пушит** | Нет registry | Выкатка новой версии не подтянет образ |
| **Нагрузочного теста не было** | Не успели | Цифры пропускной способности не измерены — **на защите не называть их как измеренные** |

## Как проверить, что всё перечисленное работает

```bash
make smoke             # 15 сквозных проверок
make test-docker       # 36 юнит-тестов + линтер
make test-integration  # 9 проверок границ доступа и изоляции кэша
make security-scan     # pip-audit + bandit
```

Проверка fail-fast руками:
```bash
docker compose run --rm --no-deps -e APP_ENV=prod --entrypoint python api -c "import app.main"
# ожидаемо падает со списком небезопасных значений
```
